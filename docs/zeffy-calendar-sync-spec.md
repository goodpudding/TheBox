# Zeffy → portal → Google Calendar sync

Brief for Cursor. One branch, one PR. Build after the live-data bridge (merged) and the RPC fix (#21).

## Why

The class schedule exists in three places that drift: the Nov/Dec schedule sheet, the CSV snapshot that became the 65 `ClassSession` rows, and the `discovermakers@gmail.com` Google Calendar (hand-entered). Staff already create every ticketed class in Zeffy. Make Zeffy the single place a class is created; the portal and the Google Calendar follow automatically.

## What Zeffy gives us (verified against https://api.zeffy.com/api/docs)

`GET /api/v1/campaigns` (Bearer `ZEFFY_API_KEY`, cursor-paginated, 100/min rate limit) returns donation forms **and events**. Event campaigns carry `start_date`, `end_date`, `occurrences[]` (each with its own start/end — used for multi-session classes like "Cutting Board A · day 1 of 2"), `rates[]` (price, `seats`, `maximum_to_buy`, `early_bird_close_date`), the public URL, and status. Check the exact field names in the "List campaigns" code sample before coding; log the first real response.

The existing client helpers are in `src/lib/zeffy/client.ts` (`listAllZeffyCampaigns`) and `src/lib/zeffy/apply-payment.ts` (`syncClassUrlsFromCampaigns`), and `scripts/sync-zeffy.ts` already fills `zeffyUrl` by `zeffyCampaignId`. Extend rather than replace.

## 1. Schema

`ClassSession` additions (migration is generated by the `db-artifacts` workflow on push; don't hand-write it):
- `source String @default("admin")` — `zeffy` | `csv` | `admin`. The 65 existing rows get `csv` in a one-off data migration statement in the same PR (`UPDATE ClassSession SET source='csv' WHERE zeffyCampaignId IS NULL`), run via `wrangler d1 execute` once after deploy — put the statement in `scripts/one-off/` and note it in the PR.
- `zeffyOccurrenceId String?` — occurrence id within the campaign; `@@unique([zeffyCampaignId, zeffyOccurrenceId])`.
- `googleEventId String?`, `googleCalendarId String?` — set after the calendar push.
- `syncedAt DateTime?`, `cancelledAt DateTime?`.

## 2. Zeffy pull — `src/lib/sync/zeffy-classes.ts`

`syncClassesFromZeffy(): Promise<{created, updated, cancelled}>`:
1. List all campaigns; keep events (not donation forms) whose end is in the future or within the last 30 days.
2. For each campaign × occurrence, upsert a `ClassSession` keyed on `(zeffyCampaignId, zeffyOccurrenceId)` with `source='zeffy'`: title, `startsAt`/`endsAt` (occurrence times; campaign dates if no occurrences), `priceCents` (lowest non-zero rate; 0 if all rates free), `capacity` (sum of rate `seats`, or the org default from `OrgSettings` if Zeffy reports none), `zeffyUrl`, `location` (Zeffy's, else the shop address), `instructorId` = the admin user configured in `OrgSettings.defaultInstructorId` (add that setting; UI in admin settings) — staff can change instructor in the admin class page afterwards and the sync must **not** overwrite fields staff edited: track `staffEditedFields String?` JSON on the row, set by `adminUpsertClass`, and skip those keys on sync.
3. A `source='zeffy'` row whose campaign/occurrence no longer appears, or is cancelled/archived in Zeffy, gets `cancelledAt` set (not deleted; bookings may reference it).
4. Never touch `source='csv'` or `source='admin'` rows.
5. Write one `AuditEvent` per run (`action: "sync.zeffy_classes"`, metadata = the counts).

## 3. Google Calendar push — `src/lib/sync/google-calendar.ts`

Runs after the Zeffy pull in the same job. Uses the Google Calendar REST API directly with a service-account JWT signed via WebCrypto (`crypto.subtle`, RS256) — **no `googleapis` package**; it doesn't run on Workers. Token exchange: `https://oauth2.googleapis.com/token`, scope `https://www.googleapis.com/auth/calendar.events`.

Env (Worker secrets/vars): `GOOGLE_SERVICE_ACCOUNT_JSON` (secret; already planned for the Drive sync), `GOOGLE_CALENDAR_CLASSES_ID`, `GOOGLE_CALENDAR_COMMUNITY_ID` (plain vars; the calendar ids from Google Calendar → settings → "Integrate calendar").

Rules:
- Which calendar: `priceCents > 0` → classes calendar; free → community calendar. Keep this as one function so it's easy to change.
- Upsert by `googleEventId`; create when null, patch when set, delete when `cancelledAt` is set (then clear the id). Event body: summary = title, description = short blurb + "Register: {zeffyUrl}" + capacity line, location, start/end with `timeZone: "America/Los_Angeles"`, `extendedProperties.private.theboxSessionId`.
- Push `source='admin'` sessions too (open shop blocks, closures created in the portal). Never push `source='csv'` rows — those are retired once Zeffy has the real events.
- The sync only ever edits events carrying `theboxSessionId`; hand-entered events on those calendars are left alone. Trey will clear the hand-entered Nov/Dec events before the first run (see go-live).
- On Google API errors, log and continue; one bad event must not stop the run.

## 4. Trigger

- `POST /api/sync/zeffy` — `runtime="nodejs"`; allowed when the request carries `Authorization: Bearer ${SYNC_SECRET}` (new Worker secret) **or** the caller is a signed-in staff user (so the admin button works). Returns the counts.
- **Scheduled:** Cloudflare Cron Trigger, hourly. OpenNext's worker only exports `fetch`, so add `src/worker.ts` that re-exports the OpenNext handler and adds a `scheduled` handler which calls the sync directly (import the lib, don't HTTP-call yourself). Point `wrangler.jsonc` `main` at the built custom worker per https://opennext.js.org/cloudflare/howtos/custom-worker and add `"triggers": { "crons": ["0 * * * *"] }`. If that fights with Workers Builds, fall back to a GitHub Actions `schedule` workflow that `curl`s the route with `SYNC_SECRET`; note which one shipped.
- Admin UI: on `/admin/classes`, a **Sync from Zeffy now** button calling the route, showing the counts and last `syncedAt`.

## 5. Go-live steps (for Trey, documented in README → "Classes & calendar")

1. Create a Google Cloud service account, download its JSON key, enable the Calendar API; add the key as `GOOGLE_SERVICE_ACCOUNT_JSON`.
2. In Google Calendar (discovermakers account), share `box classes` and `community classes` with the service-account email, permission "Make changes to events". Copy their calendar ids into the two vars.
3. Delete the hand-entered Nov/Dec events from those two calendars (or create fresh calendars and retire the old ones), so only synced events appear.
4. Recreate the Nov/Dec classes in Zeffy as events (paid ones as ticketed; make nights as free-ticket RSVP events if desired). Run **Sync from Zeffy now**. Verify the calendar.
5. Run the one-off `source='csv'` statement, then use the admin bulk action **Archive CSV-imported sessions** (sets `cancelledAt` on `source='csv'` rows; add this action) so the public classes page shows only Zeffy-sourced classes.
6. Embed the Google Calendar on the Discover Burien Squarespace "Makerspace Classes" page instead of hand-posting there.

## Tests

- `zeffy-classes.test.ts`: fixture campaign JSON (one single-date event, one with two occurrences, one free, one archived) → correct upserts, price/capacity derivation, `cancelledAt` on disappearance, staff-edited fields preserved, csv/admin rows untouched.
- `google-calendar.test.ts`: JWT builder produces a verifiable RS256 token (test key); request bodies for create/patch/delete; errors on one event don't abort the batch.
- Route test: no secret and no staff session → 401; staff session → runs.

## Acceptance

1. Create a test event in Zeffy → within an hour (or on "Sync now") it appears on `/classes` with the right time, price, seats and Register link, and on the Google Calendar.
2. Change its time in Zeffy → both update. Archive it in Zeffy → it disappears from the calendar and shows cancelled in admin.
3. Edit the instructor in the portal admin → the next sync keeps that edit.
4. An open-shop block created in the portal admin appears on the community calendar.
5. Hand-entered events on the calendars are never modified.
